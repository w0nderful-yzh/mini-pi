# M7.8.2 输入 Token 估算对拍

2026-09-28 用 `deepseek-flash`、`DeepSeekClient.complete()` 的流式 usage 对拍。运行 `uv run python docs/benchmarks/m7_8_token_estimation.py` 可重放固定请求；脚本只打印尺寸与数字，不输出 Key 或模型回复。四组均使用同一条短 system 提示。实际值是 Provider 返回的 `usage.input_tokens`，偏差按 `预测 / 实际 - 1` 计算。

| 样本 | 用户文本字符 | 工具数 | 旧估算（4 字符/token） | 新估算 | 实际 input | 新偏差 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 中文重复段落 | 408 | 0 | 121 | 292 | 288 | +1.4% |
| 英文重复段落 | 864 | 0 | 235 | 210 | 189 | +11.1% |
| 中英混合重复段落 | 852 | 0 | 232 | 294 | 282 | +4.3% |
| 短中文 + 文件读取 schema | 6 | 1 | 137 | 360 | 372 | −3.2% |

工具开销另用同一短文本对照：无工具 40 input tokens；一个简短 `ping` schema 为 279；一个文件读取 schema 为 372；两个工具同时传入为 400。差额主要发生在**启用工具模式**时，不应按每个工具重复加固定开销。旧估算对该文件读取 schema 请求低估 63.2%。

本次规则：ASCII 每字符 0.2 token；东亚文字与标点每字符 0.625；其他宽字符每字符 1；非 ASCII 窄字符每字符 0.5，累积后向上取整。wire 消息请求加 18 token，非空工具集加一次 210 token，再计工具 JSON schema 的加权字符。工具模式固定值由上述对照校准；其他宽字符和非 ASCII 窄字符目前是保守系数，尚无对应 Provider 样本。

本里程碑对四组固定请求的验收容差为相对误差 ±15%，中文样本还要求不低估；四组均达到。该容差只说明这组样本。长真实会话、OpenAI、其他 DeepSeek 模型以及工具很多时的偏差尚未量化，因此下一请求始终标为 `estimated`，历史 Provider usage 仅作为历史实测保存。摘要切点的 `usage.total_tokens` 锚点与下一请求预测保持分离。
